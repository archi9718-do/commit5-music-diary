## 1. 무엇을 왜 만드나

"뭐야", "아 진짜"처럼 짧은 말은 글만 보고는 감정을 자주 틀린다. 같은 글자라도 목소리(높낮이, 세기, 빠르기)에 따라 기쁨일 수도, 짜증일 수도 있다. 녹음으로 기록할 때는 목소리가 이미 서버에 들어오므로, 목소리로 감정 확률을 하나 더 구해 글 감정 확률과 합친다.

지금 녹음 경로(`backend/app/main.py`의 `_voice_to_result`)는 받아쓴 글만 `_analyze_and_save`로 넘긴다. 목소리 자체는 감정 판단에 쓰지 않는다.

## 5. 접근 방식 (합치는 방법)

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **1 (채택)** | 고정 가중치 하나: `최종 = (1−w)·글 + w·목소리`, w는 검증 세트에서 0.0~1.0을 0.1 간격으로 고른다 | 숫자 하나, 설명 쉬움, 과적합 위험 가장 적음 | 긴 글에도 같은 비중 |
| 2 (비교표만) | 글 길이별 가중치 두 개 (10자 이하 `w_short`, 그 외 `w_long`) | 짧은 말 보완이라는 목적에 직접 맞음 | 짧은 말 표본이 약 1,300개라 `w_short`가 흔들림 |
| 3 (뺌) | 글 확률 + 목소리 특징을 함께 넣는 합침 분류기 학습 | 가장 유연 | 학습할 것이 늘고 과적합 위험, 발표에서 설명하기 어려움 |

상현이 1번으로 서비스를 정하고 2번은 비교표에만 넣기로 했다 (11-26). 2번이 짧은 말에서 확실히 나으면 그때 바꾼다.

## 6. 학습과 평가

**특징** (Claude 제안): 인코더 마지막 층 출력의 시간 평균 (768차원). wav는 `ai/stt/benchmark_whisper.py`의 `load_wav_16k`로 16kHz로 바꾸고 앞 10초만 쓴다. 특징은 인코더별로 `C:\work\moodwave_data\features\` 아래 파일 하나에 저장해 두고(재실행 시 다시 뽑지 않음) 학습은 그 파일만 읽는다.
- 추출 시간(계산값): 2차 4종 11,686개 기준 인코더당 약 1~1.5시간.

**분류기** (Claude 제안): torch 선형 층 하나 (768 → 4). 감정별 개수가 달라 교차 엔트로피에 클래스 가중치를 준다. 검증 macro-F1로 조기 종료한다.

**인코더 선택**: wav2vec2-base와 HuBERT base를 같은 조건으로 학습해 검증 macro-F1이 높은 쪽을 쓴다.

**글 확률**: 검증·평가 문장의 `발화문`을 지금 글 모델(`analyze_text`, klue-bert)에 넣어 확률을 구한다. CSV의 발화문을 그대로 쓴다 (받아쓰기 오류는 이 비교에 넣지 않는다).

**지표**: 4종 macro-F1 (주), 정확도, 감정별 F1. 짧은 말(발화문 10자 이하)은 따로 계산한다.

**비교표** (평가 세트, 전체 / 짧은 말)

| 방법 | macro-F1 | 정확도 |
|---|---|---|
| 글만 | | |
| 목소리만 | | |
| 합침 (w 하나) | | |
| 합침 (w_short, w_long) | | |

**서비스에 켜는 기준** (Claude 제안): 평가 세트에서 아래 두 가지를 모두 만족할 때만 켠다.
1. 전체 macro-F1: 합침이 글만보다 1%p 이상 높고, 평가 문장을 다시 뽑는 부트스트랩(1,000회) 95% 구간의 아래쪽이 0보다 크다.
2. 짧은 말 macro-F1: 합침이 글만보다 낮지 않다.

검증에서 고른 w가 0.0이면 목소리가 도움이 안 된다는 뜻이므로 켜지 않는다.

**확신도 기준 재확인**: 합친 확률로 평가 세트의 "높음"(0.7 이상) 비율과 "높음"일 때 정확도를 글만과 나란히 적는다. `HIGH = 0.7`은 상현·건호 합의값이므로 이 작업에서 바꾸지 않는다. 바꿀 필요가 보이면 숫자를 들고 따로 정한다.

**결과 기록**: 비교표, 고른 인코더, w, 확신도 표를 README에 적는다. 학습된 분류기와 메타 파일(인코더 이름, w, 평가 점수, 켜기 판정)은 `C:\work\moodwave_data\models\voice-emotion\`에 둔다.

## 8. 서비스 연결 (켜기 판정이 났을 때만)

**새 코드 위치** (Claude 제안): `ai/voice_emotion/`. 데이터 준비·특징 추출·학습·평가 스크립트와 서비스 창구 `service.py`를 둔다. 서비스 창구는 `ai/emotion/service.py`와 같은 모양을 따른다.
- `warm_up()`: 서버가 켜질 때 인코더와 분류기를 미리 읽는다.
- `predict_probs(audio_16k: np.ndarray) -> dict`: 4종 확률.
- 모델 폴더는 환경 변수 `MOODWAVE_VOICE_MODEL_DIR`, 없으면 기본 폴더. 폴더가 없거나 메타 파일의 켜기 판정이 거짓이면 목소리를 쓰지 않는다 (글만).

**합치는 곳**: `backend/app/main.py`
- `_voice_to_result`에서 `stt_service.transcribe(audio)` 뒤, 받아쓴 글 검사를 모두 통과한 다음에 목소리 확률을 구한다. 음성은 `ai/stt/service.py`의 `decode_audio(bytes)`로 메모리에서 16kHz로 바꾼다 (`load_wav_16k`는 파일 경로를 받으므로 서비스에서는 쓰지 않는다). 원본 음성은 디스크에 쓰지 않는다.
- `_analyze_and_save(text, participant, voice_probs=None)`로 넘기고, `analyze_text` 결과의 probs를 w로 합친 뒤 `emotion`과 `confidence`(`get_confidence`)를 다시 정한다. 반올림·합 1 맞추기는 `ai/emotion/emotion_mapper.py`의 `fix_probs_sum`을 그대로 쓴다. `confidence`는 반올림한 값으로 정한다 (`predict_emotion`과 같다). 그다음 기존 `EmotionResult` 검사와 저장을 그대로 탄다.
- 목소리 모델이 준비되지 않았거나 예외가 나면 `_log_model_failure("목소리 감정", exc)`로 남기고 글 결과만 쓴다. 503을 내지 않는다.
- 녹음 경로의 다른 응답(400, 422 `uncertain_transcript`, 503 받아쓰기)은 바꾸지 않는다.

**속도 확인**: 서비스 연결 뒤 시연 PC에서 10초 녹음 기준 확인 화면까지 시간을 다시 잰다. 5초를 넘으면 켜지 않는다.

## 9. 시험

- 라벨: 대소문자 정리, 다수결(3/5 이상), 4종 밖 감정 제외, 4번 세기 열 이름 차이.

- 시험에는 AI Hub 데이터를 넣지 않는다 (가짜 값과 짧은 합성 소리만 쓴다).
