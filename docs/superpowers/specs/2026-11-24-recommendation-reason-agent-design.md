## 1. 무엇을 왜 만드나

추천 3곡마다 "왜 이 곡인지"를 한 줄로 보여 준다. 지금 화면은 서버가 준 단계 이름(`step`, 예: "조금 밝게")을 그대로 이유 칸에 쓴다(`frontend/src/api.js`의 `lpTracks`: `reason: song.step`).

이번 주(11월 4주차) 할 일이 "에이전트(곡별 추천 이유 한 줄, 금지 표현 검사)"이고, README 8절에 지표를 걸어 두었다.

| 지표 | 목표 |
|---|---|
| 에이전트 출력 형식 준수율 | 95% |
| 도구 결과 밖 내용(환각) | 0건 |
| 위험 표현 문장에 상담전화 109 안내 | 100% |

마음을 다루는 앱이라 LLM이 위로·진단처럼 들리는 말을 할 위험이 있다. 그래서 **LLM은 문장을 다듬기만 하고, 사용자는 언제나 검사를 통과한 문장이나 템플릿 문장만 본다.**

## 5. 흐름

```
감정 확정 → POST /api/recommendations (지금 그대로, 단계 이름을 이유로 즉시 표시)
          → 화면이 이어서 POST /api/records/{record_id}/reasons
               ├ 위험 표현 기록 → LLM 안 부름, {"source":"template","risk":true}
               ├ 키 없음·시간 초과·오류·검사 탈락 → {"source":"template"}
               └ 통과 → {"source":"agent"}  화면이 3곡의 이유 칸을 바꿈
```

- 화면은 추천 화면을 먼저 보여 주고 이유 요청을 기다리지 않는다. 응답이 오면 그 자리의 문장만 바꾼다.
- 이유 요청이 실패해도 화면에 오류를 띄우지 않는다 (템플릿 문장이 이미 보임).

## 6. API

### `POST /api/records/{record_id}/reasons`

요청 본문 없음. 응답:

```json
{
  "source": "agent",
  "risk": false,
  "reasons": [
    {"recommend_order": 1, "text": "지금 마음처럼 낮고 잔잔한 곡으로 시작해요."},
    {"recommend_order": 2, "text": "밝기를 조금 올려 천천히 이어가요."},
    {"recommend_order": 3, "text": "한결 밝은 곡으로 오늘을 마무리해요."}
  ]
}
```

- `source`: `"agent"` 또는 `"template"`. `template`이면 `reasons[].text`는 템플릿 문장(7.4절)
- `risk`: 기록 글에 위험 표현이 있으면 `true`. 화면은 `true`면 `risk` 화면(109 안내)으로 보낸다
- 404: 기록이 없음. 409: 아직 추천 전(`tb_record_song` 3행 없음)
- 응답 양식은 언제나 3줄. 서버 오류도 가능하면 `template`으로 돌려준다 (5xx를 줄임)
- 결과를 DB에 저장하지 않는다. 화면이 받은 문장을 그날 기록(`moodwave.mvp.records.v1`의 곡 정보)에 함께 저장한다
- 같은 기록으로 다시 부르면 다시 생성한다 (비용은 1회 약 $0.01)

## 7. 에이전트 (`ai/agent/`)

글 감정(`ai/emotion/service.py`), 받아쓰기(`ai/stt/service.py`)와 같은 모양으로 `ai/agent/service.py`를 둔다. 서버는 `write_reasons(...)` 하나만 부른다. DB 조회는 서버가 함수로 넘겨 주고, 에이전트는 DB를 직접 열지 않는다.

### 7.1 도구 3개

| 도구 | 돌려주는 것 | 출처 |
|---|---|---|
| `get_today` | `confirmed_emotion`, `taste_side`(있으면, 취향 유형 작업 4가 병합된 뒤) | `tb_record` |
| `get_songs` | 곡 3개: `recommend_order`, `step`, `brightness`, `energy` (0~1) | `tb_record_song` |
| `get_recent_moods` | 지난 7일(오늘 제외) 날짜별 `emotion_final` 목록, 없으면 빈 목록 | 같은 `user_id`의 `tb_record` |

- 도구는 입력 인자가 없다 (기록 id는 서버가 이미 정함). 모델이 다른 기록을 볼 수 없다.
- 반복은 최대 4번. 넘으면 `template`.

### 7.2 출력 형식

마지막 답은 구조화 출력(JSON 스키마)으로 받는다:

```json
{"reasons": [{"recommend_order": 1, "text": "..."}, {"recommend_order": 2, "text": "..."}, {"recommend_order": 3, "text": "..."}]}
```

### 7.3 검사기 (통과 못 하면 `template`)

한 줄이라도 걸리면 3줄 모두 템플릿으로 바꾼다 (섞어 보이지 않음).

1. **형식**: `recommend_order`가 1, 2, 3 각각 한 번. `text`는 한 줄, 15~45자, "요"로 끝남, 이모지·따옴표·영문 없음
2. **금지 표현** (목록은 `ai/agent/rules.py`에 둔다. 초안, 상현이 고침)
   - 진단·병명: 우울증, 공황, 장애, 치료, 진단, 증상, 상담이 필요
   - 약속·단정: 괜찮아질 거, 나아질 거, 반드시, 분명히, 틀림없이
   - 명령·훈계: 힘내, ~해야 해요, ~하세요
   - 다른 사람 언급, 일기 내용 추측: 친구, 가족, 회사, 학교, 시험
   - 곡의 효과(기분·마음·몸을 바꿔 준다는 말): 감싸, 누그러, 숨을 고, 끌어올 등 (11/25 판정 26/143이 모두 이 종류라 추가)
3. **사실 확인** (도구 결과 밖 내용 막기)
   - 숫자가 나오면 금지 (밝기·에너지 숫자를 문장에 쓰지 않음)
   - 감정 단어는 확정 감정의 것만 (가라앉음 날에 "신나는" 등 다른 감정 단어 금지. 감정별 단어 목록은 `rules.py`)
   - 곡 제목·아티스트·악기·장르 단어 금지 (도구가 주지 않음. 목록은 `rules.py`)
   - 최근 7일을 언급하면(`요즘`, `며칠`, `이번 주`) `get_recent_moods`가 비어 있지 않아야 함

### 7.4 템플릿 문장

`step`마다 한 줄을 `rules.py`에 둔다 (단계 이름 8개 표 × 3단계, 취향 유형 작업 전에는 4개 표). 예: `"조금 밝게"` → "밝기를 조금 올려 이어가요." 템플릿 문장도 7.3절 검사를 통과해야 한다 (시험으로 확인).

### 7.5 위험 표현

`frontend/src/domain.js`의 `SIGNALS`(정규식 7개)와 같은 목록을 `ai/agent/rules.py`에 둔다. 기록 글이 하나라도 맞으면 LLM을 부르지 않고 `risk: true`.

- 화면은 이미 위험 표현 기록을 추천 전에 109 화면으로 보낸다. 서버 쪽은 화면을 거치지 않은 요청을 막는 두 번째 겹이다.
- 두 목록이 어긋나지 않게, 같은 시험 문장 묶음을 프론트·백엔드 시험이 함께 쓴다 (`backend/tests/fixtures/risk_sentences.json`).

### 7.6 호출 설정

- 모델 `claude-opus-5-5`, `output_config.effort="low"`, 생각 표시는 기본값
- 서버가 기다리는 시간은 최대 10초 (SDK `timeout`), 재시도 1번
- 시스템 프롬프트는 고정 문자열 (캐시가 깨지지 않게 날짜·id를 넣지 않음)
- 거절(`stop_reason == "refusal"`)·최대 토큰 도달·도구 반복 초과는 모두 `template`
- 키가 없으면 서버는 켜지고 이 경로만 언제나 `template` (받아쓰기·글 감정과 같은 원칙)

## 8. 화면

- `accept()`에서 추천을 받은 뒤, `draft.demo`가 아니면 `POST /records/{id}/reasons`를 기다리지 않고 부른다
- 응답이 `risk: true`면 `go("risk")`
- `source: "agent"`면 `draft.queue`의 `reason`을 바꾼다. 사용자가 이미 다른 화면으로 넘어갔거나 같은 날 다시 기록했다면(`recordId`가 바뀜) 버린다
- 이유 칸에 작은 표시를 하지 않는다 (사용자에게는 문장만). 출처는 평가 스크립트로만 본다

## 9. 평가 (`ai/agent/eval.py`, 지표 3개)

일회용이 아니라 저장소에 둔다 (발표 때 다시 잼).

- **입력 묶음**: 감정 4종 × 쪽 2개 × 최근 7일(없음 / 같은 감정 반복 / 섞임) = 24경우 × 5번 = 120회 (약 $1~2). 실제 DB 없이 도구 결과를 가짜로 넣는다
- **형식 준수율**: 검사기 1번(형식)을 통과한 비율. 목표 95%
- **환각**: 검사기 3번에 걸린 수 + 상현이 120개 출력을 직접 읽고 "도구 결과 밖 내용"을 센 수. 출력은 `C:\work\moodwave_data\agent_eval\`에 CSV로 남긴다 (저장소 밖). 목표 0건 (사용자에게 보인 문장 기준, 즉 검사기 통과분)
- **109 안내**: `risk_sentences.json`의 위험 문장 전부에 대해 화면 `classify()`와 서버 검사가 모두 위험으로 판단하는 비율. 목표 100%. LLM 호출 없음
- 금지 표현에 걸린 수도 함께 보고한다
