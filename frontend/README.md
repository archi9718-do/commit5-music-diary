# MoodWave React MVP

글로 기분을 기록하고, 음악을 감상해 오늘의 LP판을 남기는 React 시제품입니다. 기록, 감정 분석, 추천곡, 곡별 반응과 LP 새김은 FastAPI 서버에 연결됩니다.

## VS Code에서 실행

1. [API 연동 명세서의 서버 실행 안내](../API_CONTRACT.md#5-로컬-서버-실행)를 따라 `backend/`에서 서버를 켭니다.
2. VS Code에서 프로젝트를 열고 별도 터미널에서 `frontend/`로 이동합니다.
3. Node.js 22.12 이상을 권장합니다. 아래 명령을 실행합니다.

```bash
npm install
npm run dev
```

4. 터미널에 표시된 Local 주소(기본 `http://localhost:5173`)를 브라우저로 엽니다.
5. 종료할 때 터미널에서 `Ctrl+C`를 누릅니다.

프론트엔드는 기본으로 `http://127.0.0.1:8000`의 API를 호출합니다. 다른 서버를 쓰려면 `VITE_API_BASE_URL`을 설정한 뒤 Vite를 다시 시작하세요. 빌드 및 로직 테스트는 각각 `npm run build`, `npm test`입니다.

## 한 번에 확인하는 경로

1. **기록 시작** → 글에 `오늘은 행복하고 뿌듯하고 즐거웠어요.` 입력 → **기록 완료**.
2. **맞아요** 또는 **다른 감정이에요**로 감정 확정 → 추천곡 세 곡과 선택 이유 확인.
3. 곡을 열고 가운데 **재생**을 누릅니다. 16초 시연 음원이 실제로 재생됩니다. 다른 곡도 끝까지 듣고(총 두 곡 이상), 한 곡은 **좋아요**를 누릅니다.
4. **곡에 반응 남기기 → 감상 마치기**. 두 곡 이상 듣지 않았다면 기분 응답 없이 LP 새김으로 이어집니다.
5. 확정 감정이 가라앉음·예민함이고 두 곡 이상 완청하면 감상 후 기분을 선택하거나 건너뜁니다. **LP판에 새기기** 또는 **기록만 저장하기**를 선택합니다.
6. **나의 LP / 내역 / 마이**에서 저장된 기록, 월별 통계, Day Type, 첫 화면 설정을 확인합니다.

`마이 → 시연 메뉴 보기`에서 높은·중간·낮은 확신, 분석 실패, 도움 안내, 오류 상태를 바로 확인할 수 있습니다. 화살표는 월별 기록을 바꾸고, 날짜 카드를 누르면 그날의 기록이 열립니다. 하루 한 건이며 같은 날짜에 다시 저장하면 덮어쓸지 묻습니다. `마이`에서 이 브라우저에 있는 기록을 지울 수 있습니다.

## 화면과 기능의 범위

| 영역 | 포함 화면 |
|---|---|
| 시작·사용자 진입 (3) | 시작, 로그인 미리보기, 회원가입 미리보기 |
| 감정 기록 (3) | 오늘의 기록, 음성 녹음 동의, 음성 녹음 |
| 분석·확인 (5) | 로딩, 높은 확신, 중간 확신, 낮은 확신, 직접 선택 |
| 음악 (4) | 추천, 감상, 반응, 감상 완료 |
| LP판 (4) | 새김 확인, 새김 완료, 오늘의 LP판, 날짜별 기록 |
| 마이·월간 (4) | 마이페이지, 월간 감정 분석, 월간 음악 취향, Day Type |
| 예외 (3) | 분석 실패, 위험 표현 도움 안내, 서비스 오류 |

- **기본 감정**은 좋음·무난함·가라앉음·예민함입니다. 글은 서버에서 분석하며, 모델을 사용할 수 없으면 네 감정 중 하나를 직접 선택합니다. 마이페이지 테스트 시나리오는 브라우저의 단어 규칙으로 동작합니다.
- **음성**은 마이크 권한을 받은 localhost에서 최대 10초간 동작합니다. 기록 완료 시 녹음을 서버에 보내 받아쓰고, 받아쓴 글로 감정을 추정합니다. 서버는 받아쓴 글과 감정 결과를 저장하며 원본 녹음은 메모리에서 처리합니다. 목소리의 억양을 이용한 감정 분류는 개발 예정입니다.
- **플레이어**는 서버 추천곡의 제목 또는 ID를 표시하고 포함된 합성 WAV를 시연용으로 재생합니다. 재생을 끝냈을 때 실제로 들은 구간이 전체 길이를 채워야 완청으로 저장합니다. 재생 위치를 앞으로 옮겨 건너뛴 구간은 완청에 포함하지 않습니다.
- **저장**은 서버의 기록 ID와 LP 화면에 필요한 데이터를 브라우저에 보관합니다. 감상 종료와 감상 후 기분은 서버에 저장되며, 같은 날 질문은 한 번만 표시합니다. 기록 목록과 월간 요약은 브라우저에 보관된 기록을 사용하며 마이페이지의 삭제 버튼도 브라우저 데이터에 적용됩니다.
- **사용자 시작 화면**은 `마이`에서 기록 입력 우선/지난 기록 우선을 직접 바꿀 수 있습니다. 행동 데이터를 수집해 자동으로 바꾸지 않습니다.

## 아직 연동하지 않은 항목

실제 로그인/회원가입, 새 기기 로그인 시 기존 세션 종료, 음성 피치 분석, 8대 감정의 조합, 외부 음악·영상 서비스 및 권리 확인, 기기 간 기록 목록 동기화, 활동 콘텐츠 추천, 외부 인기 차트 및 모델 기반 Day Type. 도움 화면은 시연 문구로 분기합니다. [한국 109 상담 안내](https://www.129.go.kr/109)

## 등록 음원 확인

서버와 프론트를 로컬에서 실행하고 시작 화면의 **등록 음원 듣기**를 누릅니다. 음원은 기본적으로 저장소의 `data/music/`에서 읽으며, 서버 환경 변수 `MOODWAVE_AUDIO_DIR`로 다른 폴더를 지정할 수 있습니다. 공개 시연 승인 값이 0인 곡은 서버 PC의 localhost에서만 들을 수 있습니다. 추천 흐름의 기존 시연 플레이어와는 별도 화면입니다.

새 PC에서는 MP3 파일과 CSV를 준비한 뒤 `backend/`에서 목록을 등록합니다. CSV 헤더는 `song_id,title,artist,filename,is_public_demo`입니다. 곡 ID는 `custom_001`처럼 지정하고 파일명은 음원 폴더 기준의 상대 경로로 작성합니다. 공개 시연에 올릴 곡만 `is_public_demo`를 `1`로 지정합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
.\.venv\Scripts\python.exe -m app.import_audio ../data/audio-manifest.csv --audio-dir ../data/music
```

등록 명령은 CSV에 있는 곡만 추가하거나 갱신합니다. 승인 취소는 해당 곡의 값을 `0`으로 바꿔 다시 등록합니다. 별도 DB를 쓰려면 등록 명령과 음원 서버에 같은 `MOODWAVE_DB_PATH`를 설정합니다.

ngrok 시연에는 음원 전용 빌드와 포트 8001을 사용합니다. 저장소 루트에서 다음 순서로 실행합니다.

```powershell
cd frontend
$env:VITE_AUDIO_DEMO_ONLY = "1"
npm.cmd run build -- --outDir ../data/audio-demo-dist --emptyOutDir
$buildExit = $LASTEXITCODE
Remove-Item Env:VITE_AUDIO_DEMO_ONLY
if ($buildExit -ne 0) { throw "음원 전용 화면 빌드 실패" }
cd ../backend
.\.venv\Scripts\python.exe -m uvicorn app.audio_demo:create_app --factory --host 127.0.0.1 --port 8001
```

다른 터미널에서 ngrok을 **음원 서버의 8001 포트**에 연결합니다. [ngrok Basic Auth 안내](https://ngrok.com/docs/gateway/traffic-policy/examples/add-authentication)에 따라 `data/ngrok-audio-auth.json`을 만들고 시연용 계정 정보를 설정합니다. 아래 명령은 저장소 루트에서 실행합니다.

```powershell
ngrok http http://127.0.0.1:8001 --traffic-policy-file data/ngrok-audio-auth.json --inspect=false
```

음원 전용 서버는 승인 값이 1인 곡만 제공합니다. 목록이 비어 있으면 CSV 등록 여부와 DB·음원 경로 설정을 확인합니다. 인증 파일, 음원, SQLite DB는 로컬에 보관합니다.

## 팀 사용자 테스트

반 친구에게 자율 참여를 요청하고 가상 일기로 같은 흐름을 체험하도록 안내합니다. 실제 개인정보나 민감한 기록은 받지 않습니다. 참여 코드를 써서 아래 항목을 따로 적습니다.

| 참여 코드 | 사용자가 고른 감정 | 시제품이 제안한 감정 | 일치 여부 | 추천 만족 1–5 | 사용 편의 1–5 | 막힌 화면·이유 |
|---|---|---|---|---|---|---|
| P01 |  |  |  |  |  |  |

질문 예시: “처음에 다음 행동이 보였나요?”, “추천 세 곡에서 좋았던 점은 무엇인가요?”, “기록 입력과 지난 기록 중 무엇을 먼저 보고 싶나요?” 일치율·만족도는 실제 테스트 후에만 보고합니다.

## 파일 위치

- `src/App.jsx` — 26개 화면, 전환 및 브라우저 동작
- `src/domain.js` — 기본 감정 규칙, 추천곡, 저장 상태, 월별 집계
- `src/styles.css` — 모바일 우선 파스텔 UI, 카드, LP판
- `public/audio/` — 외부 음원을 사용하지 않은 시연용 WAV
- `tests/domain.test.js` — 감정 분기, 추천·완청·LP 저장, 월별 조회 테스트
